# Complexity Router — 복잡도 분류 기준

> 요청을 Micro / Sprint / Council로 분류하는 기준.

---

## Micro — 직접 처리

**특성**: 1단계, 1파일, 모호성 낮음, 트레이드오프 없음.

**신호**:
- 특정 파일, 수치, 용어를 지목하는 요청
- 1~2개 파일 읽으면 답이 나옴
- 대안을 비교할 필요 없음
- 2분 이내 처리 가능

**업무 예시**:
- "inventory.csv에서 말차파우더 재고 얼마야?"
- "이번 달 KPI가 기준 내인지 확인해줘"
- "이 코드 체계 규칙이 뭐야?"
- "이 엑셀 열어서 3행 수정해줘"

**동작**: 스킬 종료. 메인 세션이 직접 처리.

---

## Sprint — 1~3개 스킬/에이전트

**특성**: 집중된 멀티스텝, 2~3개 관점 유용, 범위 한정.

**신호**:
- 분석 + 보고서처럼 2~3단계 조합
- 하나의 주제/데이터셋에 집중
- 5~15분 소요

**업무 예시**:
- "이 CSV 분석하고 대책서 초안 써줘" → `data-analyst` + `content-draft`
- "이 분석 결과 크로스체크하고 엑셀로 만들어줘" → `cross-check` + `xlsx`
- "지연 패턴 리서치해줘" → `deep-research`
- "경쟁사 분석해서 PPT로 만들어" → `competitive-analysis` + `pptx`

**스킬 조합 패턴**:

| 작업 유형 | 추천 스킬 |
|----------|----------|
| 분석 → 보고서 | data-analyst → content-draft |
| 분석 → 검증 | data-analyst → cross-check |
| 분석 → 파일 | data-analyst → xlsx / docx / pptx |
| 리서치 → 정리 | deep-research → content-draft |
| 전체 흐름 | data-analyst → cross-check → xlsx |

**동작**: 선택된 스킬 순차/병렬 실행. 결과 종합.

---

## Council — 3~5개 독립 에이전트

**특성**: 전략적, 고위험, 다차원. 여러 관점이 있어야 맹점 방지.

**신호**:
- 여러 부서/이해관계자에 영향
- 유효한 대안이 여러 개이고 트레이드오프가 큼
- 되돌리기 어려운 결정
- 데이터/도메인/리스크/실행 등 다른 각도에서 볼 필요

**업무 예시**:
- "A 거래처에서 B로 바꿔야 할까?"
- "이번 분기 매출 예측이 신뢰할 만한가?"
- "이 프로세스 변경을 진행해도 되는지 전체적으로 평가해줘"
- "신규 사업 추가하는 게 맞을까?"
- "실적 저하가 반복되는데 근본 원인이 뭐고 어떻게 해야 할까?"

**동적 관점 선택** (요청에 따라 3~5개 선택):

| 관점 | 초점 | 항상 포함? |
|------|------|----------|
| 데이터 분석가 | 숫자, 통계, 사실 | ✓ (항상) |
| 도메인 전문가 | 업계 관행, 해당 업무 맥락 | 도메인 의존 시 |
| 비판가 | 리스크, 실패 모드 | 의사결정 시 ✓ |
| 실행자 | 현실 제약, 비용, 일정 | 실행 여부 판단 시 |
| 고객/사용자 관점 | 최종 사용자 영향 | 외부 영향 있을 때 |

**동작**: 독립 에이전트 병렬 실행 → Independence Protocol 적용 → 종합 → 판정(Go/Pivot/No-Go).

---

## 엣지 케이스

| 상황 | 처리 |
|------|------|
| 복잡도 불명확 | Sprint으로 시작. 결과가 더 복잡하면 Council로 에스컬레이션 |
| 사용자가 "council" 명시적 요청 | 무조건 Council (복잡도 무시) |
| 사용자가 "빠르게 해줘" | Micro 또는 Sprint (Council 건너뜀) |
| Micro로 시작했는데 커짐 | 중간에 재평가. 필요하면 Sprint으로 에스컬레이션 |
| 적합한 스킬이 1개뿐 | Sprint 1개도 유효. 인위적으로 늘리지 않기 |
