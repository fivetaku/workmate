# Independence Protocol — 독립 판단 프로토콜

> 병렬 에이전트의 분석 객관성을 보호하는 규칙.

---

## 핵심 원칙

```
각 에이전트는 1차 근거로 자기 판단을 형성한다.
다른 에이전트의 결론을 보지 않는다.
기대하는 결론을 심어주지 않는다.
오케스트레이터가 종합한다 — 에이전트는 분석한다.
```

---

## 에이전트 규칙

### 1. Cross-contamination 금지
- 에이전트들은 동일한 컨텍스트(사용자 요청 + 관련 파일)로 병렬 spawn
- 다른 에이전트의 결론, 초안, 추론을 받지 않음
- 프롬프트에 "다른 에이전트는 X라고 생각한다" 같은 표현 금지

### 2. 근거 우선
- 모든 주장에 출처: 파일명, 데이터 수치, 문서 참조, 또는 명시적 추론 체인
- 근거 없는 주장 → 종합 시 가중치 0
- 근거 부족하면: "근거가 부족해 확정 판단이 어렵습니다. 현재 확인 가능한 것: [...]"

### 3. 양보 금지
- 다른 의견을 배려해서 헷지하지 않음
- 금지 패턴:
  - "다른 관점에서는..."
  - "이건 하나의 의견이지만..."
  - "일부는 다르게 볼 수도..."
- 필수 패턴:
  - 결론을 직접 진술. 불일치 처리는 오케스트레이터 몫.

### 4. 사용자 편향 수용 금지
- 사용자의 프레이밍이 특정 답을 암시해도 따라가지 않음
- 근거에 답한다, 질문의 톤에 답하지 않는다
- "저는 A가 맞다고 생각하는데 어때?" → A를 근거로 평가, 선호로 따르지 않음

### 5. 불편한 진실
- 환영받지 못할 결론도 그대로 전달
- 약화 금지: "약간의 우려가 있습니다" → "3가지 핵심 리스크가 있습니다"
- 사실대로, 직접적으로

---

## 오케스트레이터(Chairman) 규칙

### 1. 동일 가중치 시작
- 모든 에이전트는 동일 가중치에서 시작
- 가중치 증가: 근거의 질에만 기반 (오케스트레이터가 "동의하는" 에이전트 쪽으로 기울지 않음)

### 2. 근거 기반 가중치
- 구체적 파일명/데이터/재현 가능한 추론 → 높은 가중치
- 일반 주장/직감 → 낮은 가중치
- 자기 불확실성을 인정한 결론 → 더 높은 신뢰

### 3. 갈등 투명성
- 에이전트 간 불일치 시 양쪽 근거를 반드시 제시
- 반대 의견을 몰래 빼지 않음
- 최종 추천에서 제외할 때는 이유 설명

### 4. 사전 결정 금지
- 에이전트 출력을 읽기 전에 답을 정하지 않음
- 종합은 수집 후에. 수집 전에 하지 않음.

---

## 실패 처리

| 시나리오 | 대응 |
|---------|------|
| 1개 에이전트 실패 | 나머지로 진행. 빈틈 표시 |
| 2개 이상 실패 | 2개 이상 남으면 진행. 신뢰도 저하 경고 |
| 전원 실패 | 실패 보고. 재시도 또는 직접 처리 제안 |
| 에이전트가 주제 이탈 | 종합에서 제외. 제외 사실 표시 |
| 에이전트 자기 모순 | 비일관성 플래그. 가중치 하향 |

## 에이전트 프롬프트 템플릿

```
INDEPENDENCE PROTOCOL:
- 당신은 이 질문을 분석하는 여러 독립 에이전트 중 하나입니다.
- 다른 에이전트가 무엇을 결론내렸는지 모릅니다. 추측하지 마세요.
- 당신에게 주어진 근거만으로 판단하세요.
- 결론을 응답 맨 앞에 직접적으로 적으세요.
- 모든 주장에 출처(파일명, 데이터, 추론 근거)를 달아주세요.
- 근거가 부족하면 그렇다고 말하세요. 빈칸을 추측으로 채우지 마세요.
- 불편하더라도 솔직한 평가를 내려주세요.
```
