# 직무별 폴더 프리셋 레퍼런스

온보딩 Phase 5에서 직무별 폴더 구조를 제안할 때 사용하는 프리셋 사전입니다.
`.kkirikkiri/` 팀 분석의 "제조업 폴더 분류 트리 재설계 리포트"를 기반으로
10개 최상위 카테고리와 30+개 하위 폴더를 정의합니다.

**원칙**:
- 제안은 **한 번만**. 승인 후 재제안 금지.
- `mkdir -p`로 안전하게 생성 (이미 존재하면 skip).
- 기존 파일 삭제/이동 금지.
- 사용자가 거절하면 적용하지 않고 state에 `folder_preset.applied: false` 기록.
- 2단계 깊이까지만 (3단계 이상 금지)
- 비서 인프라(`.claude/`, `data/`, `references/`, `memory/`, `reports/`)는 건드리지 않음

## 전체 트리 (10개 카테고리)

모든 직무가 공유하는 워크스페이스 구조는 아래와 같습니다.
직무 프리셋은 이 중 **자신과 관련된 카테고리만 선택적으로 생성**합니다.

├── 00-system/                   ← 시스템 설정 (이미 존재)

│   ─── 제조 업무 영역 ───
│
├── 10-design/                   ← 설계/개발 (R&D)
│   ├── cad/                     ← 3D/2D CAD, BOM, ECN/ECO, PCB
│   ├── prototype/               ← 시제품, Mock-up, 3D 프린팅
│   ├── mold/                    ← 금형 설계/사양/트라이 리포트/사출조건
│   ├── cmf/                     ← Color/Material/Finish
│   └── simulation/              ← FEA, CFD, Moldflow, 공차분석
│
├── 20-production/               ← 생산/공정
│   ├── plan/                    ← 생산계획, 작업지시, 실적
│   ├── process/                 ← 공정조건표, PFMEA, Control Plan, PPAP
│   └── equipment/               ← 설비대장, PM, 금형관리, 계측기/MSA
│
├── 30-quality/                  ← 품질
│   ├── inspection/              ← IQC/IPQC/OQC 검사 기준·성적서
│   ├── ncr-capa/                ← NCR, CAR/CAPA, 8D, 클레임
│   └── spc/                     ← SPC 관리도, 공정능력분석
│
├── 40-testing/                  ← 시험/인증
│   ├── test-report/             ← 신뢰성, EMC, 환경, 수명 시험
│   ├── certification/           ← KC, UL, CE, FCC, ISO, HACCP
│   └── compliance/              ← RoHS, REACH, MSDS, VOC
│

│   ├── po-quotation/            ← 발주서, 견적서, 견적비교표, 납품서

│
├── 60-admin/                    ← 경영지원
│   ├── accounting/              ← 세금계산서, 원가, 전표, 결산
│   ├── contract/                ← 계약서, NDA, 금형소유권, 하도급
│   ├── hr-safety/               ← 인사, 교육, 안전, 위험성평가
│   └── trade/                   ← 수출입, B/L, 원산지증명, 통관
│
├── 70-sales/                    ← 영업/마케팅
│   ├── proposal/                ← 제안서, 카탈로그, 브로슈어

## 1. 생산관리 (production-control)

**핵심 카테고리**: `20-production/` (3개 하위) + `85-project/` + `90-report/` + `99-archive/`

```
20-production/
├── plan/              # 월/주/일 생산계획, 작업지시서, 실적, 4M 변경, CAPA, 택트/라인밸런싱
├── process/           # 공정조건표, PFMEA, Control Plan, Cpk, IQ/OQ/PQ, PPAP, 양산이관
└── equipment/         # 설비대장, 이력카드, 일상/정기 점검, PM, 금형관리, 계측기, MSA, 치공구

85-project/
└── {PRJ-코드}/        # 양산 이관 프로젝트별 WBS/이슈/Lessons Learned

90-report/
├── daily/             # 생산일보, 가동률
├── weekly/            # 주간 생산회의 자료
├── monthly/           # 생산달성률, OEE, 수율
└── executive/         # 경영진 보고

99-archive/            # 완료 프로젝트, 폐기 금형 이력
```

**이 프리셋이 맞는 이유**:
- 생산 계획/공정/설비 3대 축이 한 루트에 정리됨
- PFMEA-Control Plan-공정조건표 연동이 `20-production/process/`에 집중
- 일일 생산일보는 `90-report/daily/`, 주간 생산회의는 `weekly/`로 자연스럽게 누적
- 4M 변경·양산이관 같은 프로젝트성 문서는 `85-project/`로 이관

## 2. 품질 / 시험인증 (quality)

**핵심 카테고리**: `30-quality/` (3개) + `40-testing/` (3개) + `60-admin/hr-safety/` + `90-report/`

```
30-quality/
├── inspection/        # IQC/IPQC/OQC 기준서·성적서, FAI, COA, 외관한도견본
├── ncr-capa/          # NCR, CAR/CAPA, 8D, 고객클레임, 불량대책서, 외주 품질
└── spc/               # X-bar R, P/C 관리도, 공정능력 Cpk/Ppk

40-testing/
├── test-report/       # 낙하/진동/온습도/방수/수명/염수분무/EMC/ESD 시험
├── certification/     # KC/UL/CE/FCC/CCC, ISO/IATF, HACCP, 할랄, 인증관리대장
└── compliance/        # RoHS, REACH, MSDS, VOC, 환경규제, 영양성분 (식품)

60-admin/
└── hr-safety/         # KRAS, 안전작업허가, MSDS, 비상대응, 소방, 산재, 아차사고

90-report/
├── weekly/            # 품질주보
├── monthly/           # 품질월보, 파레토, 수율 분석
└── executive/         # 경영진 품질 보고
```

**이 프리셋이 맞는 이유**:
- 품질(`30-quality/`)과 시험인증(`40-testing/`)을 완전히 분리 — 운영 성격이 다름
- 환경 규제(RoHS/REACH/MSDS)는 `compliance/` 하위로 묶어 수출 대응 시 한 곳에서 조회
- 품질 시스템 문서(품질매뉴얼/절차서/내부심사)는 `80-knowledge/manual/`에 연계 (별도 하위 생성 안 함)
- 안전/환경(KRAS/MSDS/산재)은 인사 안전과 함께 `60-admin/hr-safety/`에 위치

## 3. R&D / 설계 (rnd-design)

**핵심 카테고리**: `10-design/` (5개 하위 전체) + `85-project/` + `80-knowledge/` (연구/벤치마크)

```
10-design/
├── cad/               # 3D CAD, 2D 도면, BOM, ECN/ECO/ECR, PCB/Gerber, 공차분석 원본
├── prototype/         # 시제품 의뢰서/검토서, STL, 3DP 조건, Mock-up, CNC 의뢰
├── mold/              # 금형 설계도면, 사양서, T1/T2/T3 트라이, 사출조건표, 금형 관리
├── cmf/               # CMF 스펙시트, 색상 시편, 도장/표면처리 사양, 렌더링
└── simulation/        # FEA(.inp/.odb), CFD, Moldflow, 간섭체크, 공차 Stack-up

85-project/
└── {PRJ-코드}/        # DR1/DR2/DR3 회의록, DFMEA, APQP, PPAP, DVP&R, 주간현황, Lessons Learned

80-knowledge/
├── benchmark/         # Teardown, 경쟁사 BOM 추정, 분해 사진, 비교표
└── research/          # 논문, 학회 발표, 시장/기술 트렌드, 특허 출원서, 특허맵, 선행기술조사
```

**이 프리셋이 맞는 이유**:
- 5개 하위(`cad/prototype/mold/cmf/simulation/`)가 설계 단계 전체를 덮음 — kkirikkiri 원 트리 그대로
- DR 회의록·DFMEA·APQP/PPAP·DVP&R 같은 프로젝트 성격 문서는 `85-project/`로 분리
- Teardown과 기술 논문은 `80-knowledge/` 하위로 — R&D 고유가 아닌 공유 자산이기 때문

## 4. 구매 / 자재 (procurement)

**핵심 카테고리**: `50-procurement/` (3개) + `60-admin/contract/` + `90-report/`

```
50-procurement/
├── po-quotation/      # PR, PO, 긴급발주, 견적서, 견적비교표, 납품서, 거래명세서
├── supplier/          # 공급업체평가, 협력사 관리대장, 단가표, 가격 협상이력
└── inventory/         # 재고현황, 안전재고, MRP, 입출고대장, LOT 추적, 폐기처리, 납기관리

60-admin/
└── contract/          # 기본거래, 단가계약, NDA, 금형소유권, 품질보증협약, 하도급, 위탁가공

90-report/
├── weekly/            # 구매 주간업무보고
└── monthly/           # 월간 KPI (납기준수율, 구매원가 절감, 재고회전율), 원가절감 실적
```

**이 프리셋이 맞는 이유**:
- PR/PO/견적/납품의 시간순 관리가 `po-quotation/`에 집중
- 공급업체 평가(반기/연)는 `supplier/`에 분리 — 주기가 다름
- LOT 추적과 재고는 생산관리 연계의 핵심이라 `inventory/`에 묶음
- 계약서는 법무 성격이라 `60-admin/contract/`로 (NDA/금형소유권/하도급 등)

## 5. 경영지원 (admin)

**핵심 카테고리**: `60-admin/` (4개 하위 전체) + `90-report/executive/`

```
60-admin/
├── accounting/        # 전자세금계산서, 매입/매출 전표, 원가계산, 제조원가, 감가상각, 예산, 결산, 부가세, 지출결의, 법인카드
├── contract/          # 기본거래, 단가계약, NDA, 금형소유권, 기술라이선스, 품질보증, 하도급, 위탁가공, 분쟁 합의, 계약관리대장
├── hr-safety/         # 조직도, 직무기술서, 교육계획/이수, 안전교육, KRAS, MSDS, 비상대응, 소방점검, PPE, 아차사고, 산재, 근태, 복리후생, 회의록, 인수인계
└── trade/             # Commercial Invoice, Packing List, B/L, AWB, 원산지증명(FTA), 수입신고필증, HS코드, 관세납부, 포워딩 견적, 수출입 실적, 출하지시

90-report/
├── monthly/           # 월간 결산, KPI
└── executive/         # 경영진 보고, 분기/연간 사업계획, 구매전략, 리스크 관리
```

**이 프리셋이 맞는 이유**:
- 회계·법무·인사·수출입 4개 영역은 **성격이 완전히 달라** 하위 폴더 분리 필수
- 법무(`contract/`)는 구매팀과 공유 영역
- 안전·산재 문서는 HR과 통합해 `hr-safety/`에서 관리 (안전관리자와 인사담당이 교차 조회)
- 수출입(`trade/`)은 물류·관세·FTA 대응 전담 폴더

## 6. 영업 / 마케팅 (sales)

**핵심 카테고리**: `70-sales/` (2개) + `90-report/`

```
70-sales/
├── proposal/          # 제품 카탈로그, 브로슈어, 영업 제안서, 판매 견적서
└── customer/          # 고객 요구사항서, 수주 관리표, 매출 실적/계획, 고객 클레임 대응, 고객별 단가표, 샘플 발송 대장, 거래선 관리대장

90-report/
├── weekly/            # 주간 영업 보고
├── monthly/           # 월간 매출 실적
└── executive/         # 경영진 매출 보고, 연간 매출 계획
```

**이 프리셋이 맞는 이유**:
- 대외 홍보(`proposal/`)와 고객 관리(`customer/`)는 용도·수명이 달라 분리
- 수주/매출/클레임은 고객 기준으로 `customer/` 안에서 cross-reference
- 매출 실적은 `90-report/`와 `70-sales/customer/` 양쪽에 저장됨 — 월/분기 보고용은 report, 고객별 누적은 customer

## 7. 프로젝트 관리 (project-mgmt)

**핵심 카테고리**: `85-project/` (프로젝트별 하위) + `90-report/weekly/`

```
85-project/
└── {PRJ-코드}/
    ├── wbs.xlsx           # WBS / 간트
    ├── dr1/               # DR1 구상 설계
    ├── dr2/               # DR2 상세 설계
    ├── dr3/               # DR3 양산 전
    ├── dfmea.xlsx
    ├── apqp-checklist.xlsx
    ├── ppap-package.zip
    ├── dvpr.xlsx
    ├── issue-log.xlsx
    └── lessons-learned.docx

90-report/
└── weekly/            # 프로젝트 주간 현황 보고
```

**이 프리셋이 맞는 이유**:
- 프로젝트별 폴더 내부에 DR/FMEA/APQP/PPAP/DVPR이 한눈에 정리됨
- 프로젝트가 끝나면 `99-archive/{PRJ-코드}/`로 이동
- 여러 프로젝트를 동시에 관리할 때 프로젝트 코드별로 독립성 보장

## 8. 기술문서 / 지식 (knowledge)

**핵심 카테고리**: `80-knowledge/` (5개 하위 전체)

```
80-knowledge/
├── datasheet/         # 부품 데이터시트(IC/센서), 소재 물성표(ABS/PC/알루미늄)
├── manual/            # 장비 매뉴얼(3D프린터/사출기), 공정 매뉴얼, SOP/작업표준서, 사용자 매뉴얼, 기술 매뉴얼
├── spec/              # 제품 사양서, 기술 규격서, 포장 사양서, 검사 기준서 마스터
├── benchmark/         # Teardown, 경쟁사 BOM 추정, 분해 사진, 스펙 비교표
└── research/          # 기술 논문, 학회 발표, 시장/기술 트렌드, 특허 출원서, 특허맵, 선행기술조사
```

**이 프리셋이 맞는 이유**:
- 외부에서 들여오는 참고 자료(`datasheet/`, `manual/`, `benchmark/`)와 사내 생성 지식(`spec/`, `research/`)이 공존
- R&D·생산·품질이 모두 조회하는 공유 지식 저장소 역할
- 특허와 리서치는 미래 제품 기획에 반복 참조

## 9. 공통 / 기타 (common)

**직무가 명확하지 않거나 여러 직무를 겸하는 경우의 기본 프리셋**

```
60-admin/
├── hr-safety/         # 회의록, 공지
└── accounting/        # 일반 경비

90-report/
├── daily/             # 일일 보고
├── weekly/            # 주간 보고

**이 프리셋이 맞는 경우**:
- 직무를 선택하지 않음 / "모르겠어요" / "여러 가지 섞여 있어요"
- 스타트업·소기업에서 한 사람이 여러 역할 겸임
- 구체적인 카테고리가 필요할 때 나중에 `/onboarding --preset-reset`으로 다시 제안 받을 수 있음

## 적용 방법 (온보딩 Phase 5에서 사용)

### 단계 1: 직무 확인
Phase 1에서 수집한 `profile` 값으로 위 9개 프리셋 중 하나 선택.

매핑:
| profile | 프리셋 |
|---------|--------|
| production-control | §1 생산관리 |
| quality | §2 품질/시험인증 |
| rnd-design | §3 R&D/설계 |
| procurement | §4 구매/자재 |
| admin | §5 경영지원 |
| sales | §6 영업/마케팅 |
| project-mgmt | §7 프로젝트 관리 |
| knowledge | §8 기술문서/지식 |
| common / null | §9 공통 |

### 단계 2: 사용자에게 제안

프리셋의 `mkdir -p` 명령 목록을 **드라이런**으로 먼저 보여줍니다:

20-production/equipment/

90-report/monthly/
90-report/executive/
99-archive/

이건 제안이고, 언제든 이름을 바꾸거나 지울 수 있어요.
이미 있는 폴더는 그대로 둡니다 (덮어쓰지 않음).
```

### 단계 3: AskUserQuestion으로 3지선다

### 단계 5: 재제안 차단

`folder_preset.applied == true`면 다음 `/onboarding` 실행 시 Phase 5를 자동 스킵합니다.
사용자가 명시적으로 `/onboarding --preset-reset`을 호출하면 재제안 가능.

## 주의사항

1. **기존 폴더와 충돌 시**: `mkdir -p`는 이미 있는 폴더를 덮어쓰지 않습니다. 내부 파일은 그대로 유지됩니다.
2. **이름 변경**: 사용자가 `20-production/` 대신 `생산/`으로 쓰고 싶다면 Phase 5 선택지에서 "일부만 적용"으로 커스터마이즈 가능.
3. **직무 변경 시**: 나중에 직무가 바뀌면 `/onboarding --preset-reset`으로 새 프리셋 제안 받을 수 있습니다. 기존 폴더는 건드리지 않습니다.
4. **여러 프리셋 혼합**: 한 사람이 생산관리 + 품질 겸임이면 Phase 5에서 "일부만 적용"으로 두 프리셋을 합쳐서 쓸 수 있습니다.
5. **40-personal 유지**: 기존 `40-personal/` 폴더가 있다면 건드리지 않습니다. 제조업 맥락에서 사용 빈도가 낮지만 사용자 결정에 맡김.
